It shows that `adversary`'s initialiser finds a valid, unsealed, executable capability left over on its
stack by the loader, spanning only 12 bytes: a sentry-selection table internal to the loader, whose
memory is later recycled as heap. A single big enough heap allocation, made from a different
compartment (`main`) using its own, unrelated allocator capability, lands on memory that overlaps the
address that leaked capability still points to.
